# T2.6 — Tela inicial e persistência

| | |
|---|---|
| **Depende de** | F0 |
| **Desbloqueia** | T2.7 |

## Objetivo

Tela onde o jogador escolhe o modo de jogo, e a camada de persistência da partida no `localStorage`.

## Escopo de arquivos

- `src/lib/storage.ts`
- `src/app/page.tsx`
- `src/components/home/` (novos arquivos)
- testes correspondentes

## O que fazer

1. **`storage.ts`:** `loadGame(): SavedGame | null`, `saveGame(game)`, `clearGame()`, chave `chess:current-game`, formato v1 da SPEC §6.5. Leitura tolerante: JSON inválido, versão diferente, campos faltando ou `localStorage` indisponível → `null`, sem lançar erro.
2. **Tela `/`:**
   - "Jogar local" → `/play?mode=local`.
   - "Jogar contra a máquina": cor (brancas / pretas / aleatório) e nível (fácil / médio / difícil) → `/play?mode=ai&color=<white|black>&level=<1|2|3>`. A cor aleatória é **resolvida aqui**, antes de navegar.
   - "Continuar partida" visível só se `loadGame()` retornar partida → `/play`.
   - Responsivo, textos em português.

## Critérios de aceite

- [ ] `saveGame` + `loadGame` devolve o mesmo objeto.
- [ ] `loadGame` retorna `null` para: chave ausente, `"{"`, `{ v: 2, … }`, objeto sem `moves`.
- [ ] `localStorage` lançando exceção não quebra `loadGame`/`saveGame`.
- [ ] A tela gera as URLs corretas para cada combinação de modo, cor e nível.
- [ ] "Aleatório" gera `color=white` ou `color=black`, nunca `random`.
- [ ] "Continuar partida" aparece somente com partida salva.

## Para o verificador

Renderização no servidor (Next.js): acesso a `localStorage` só no cliente, sem erro de hidratação.
