## Objetivo

Rodar a busca fora da thread principal e expor a IA para a UI por um hook simples.

## Escopo de arquivos

- `src/ai/levels.ts`, `src/ai/worker.ts`
- `src/hooks/useEngine.ts`
- testes correspondentes

## O que fazer

1. **`levels.ts`:** nível 1 = `maxDepth: 2`, `randomMarginCp: 150`; nível 2 = `timeLimitMs: 500`; nível 3 = `timeLimitMs: 2000`.
2. **`worker.ts`:** ao receber `search`, monta a posição (FEN inicial + lances UCI via `uciToMove`/`makeMove`), roda `search` com as opções do nível e responde `bestmove`; `stop` faz `shouldStop` retornar verdadeiro; erros viram mensagem `error`. Lógica separada em função pura testável (o `onmessage` só delega).
3. **`useEngine.ts`:** cria o Worker uma vez (`new Worker(new URL("../ai/worker.ts", import.meta.url))`), encerra ao desmontar; expõe `requestMove({ initialFen, moves, level }) → Promise<uci>`, `cancel()` e `thinking: boolean`. Gera `requestId` e **descarta respostas antigas** (SPEC §5.4).

## Critérios de aceite

- [ ] Handler puro: dado `search` com FEN + lances, retorna `bestmove` com lance legal; lance UCI inválido no histórico gera `error`.
- [ ] Nível 1 com a mesma semente produz o mesmo lance (determinismo); sementes diferentes podem variar.
- [ ] Repetição: o histórico enviado é usado (posição com repetição disponível é avaliada como empate).
- [ ] Hook (com Worker simulado): `thinking` verdadeiro durante a busca; resposta com `requestId` antigo é ignorada após `cancel()`.
- [ ] `npm run build` empacota o Worker sem erro.

## Para o verificador

`stop` antes de completar a profundidade 1, duas requisições seguidas (só a última vale), desmontagem com busca em andamento.
