# T2.3 — Web Worker, níveis e hook `useEngine`

|---|---|

## Objetivo

Rodar a busca fora da thread principal e expor a IA para a UI por um hook simples.

## Escopo de arquivos

- `src/ai/levels.ts`, `src/ai/handler.ts`, `src/ai/worker.ts`
- `src/hooks/useEngine.ts`
- testes correspondentes

## O que fazer

1. **`levels.ts`:** `levelOptions(level, seed?)` — nível 1 = `maxDepth: 2`, `randomMarginCp: 150`, `rng: createRng(seed)`; nível 2 = `timeLimitMs: 500`; nível 3 = `timeLimitMs: 2000`.
2. **`handler.ts`:** `handleSearch(request)` monta a posição (FEN inicial + lances UCI via `uciToMove`/`makeMove`), roda `search` com `levelOptions(level, seed)` e retorna `bestmove` (lance em UCI); qualquer falha vira `error`. Função pura, testável sem Worker.
3. **`worker.ts`:** só liga `onmessage` a `handleSearch` e faz `postMessage` da resposta.
4. **`useEngine.ts`:** cria o Worker (`new Worker(new URL("../ai/worker.ts", import.meta.url))`), encerra ao desmontar; implementa o contrato `UseEngine` (`requestMove`, `cancel`, `thinking`). Gera `requestId` e **descarta respostas antigas**; `cancel()` encerra o Worker e cria outro (SPEC §5.4 — não existe mensagem `stop`).

## Critérios de aceite

- [ ] Handler puro: dado `search` com FEN + lances, retorna `bestmove` com lance legal; lance UCI inválido no histórico gera `error`.
- [ ] Nível 1 com a mesma semente produz o mesmo lance (determinismo); sementes diferentes podem variar.
- [ ] Repetição: o histórico enviado é usado (posição com repetição disponível é avaliada como empate).
- [ ] Hook (com Worker simulado): `thinking` verdadeiro durante a busca; resposta com `requestId` antigo é ignorada após `cancel()`.
- [ ] `npm run build` empacota o Worker sem erro.

## Para o verificador

`cancel()` com busca em andamento seguido de nova requisição, duas requisições seguidas (só a última vale), desmontagem com busca em andamento.
