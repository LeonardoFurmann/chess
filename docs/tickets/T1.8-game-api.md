## Objetivo

Expor o motor para a UI por uma API **imutável**, que esconde completamente a `Position`.

## Escopo de arquivos

- `src/engine/game.ts`
- `src/engine/game.test.ts`

## O que fazer

Implementar as funções declaradas em `game.ts`, usando os tipos de `src/engine/types.ts`:

- `Game` guarda FEN inicial + lances (internamente pode manter uma `Position` em cache, desde que nunca seja exposta nem mutada após a criação do `Game`).
- `createGame(fen?)`, `play(game, moveInput)` (lança erro em lance ilegal ou após o fim da partida), `undo(game)` (sem lances: retorna o mesmo estado equivalente).
- Consultas: `getLegalMoves`, `getLegalMovesFrom(square)`, `getBoard` (64 posições, a1 = 0), `getTurn`, `getFen`, `getHistory` (`GameMove[]` com SAN e UCI), `getLastMove`, `getInitialFen`, `getUciMoves`.
- `getStatus`: `playing` / `checkmate` (com vencedor) / `stalemate` / `draw` com motivo (`fifty-move`, `threefold`, `insufficient-material`) + `inCheck`. **Precedência:** mate > afogamento > material insuficiente > tripla repetição > 50 lances.
- Todos os objetos retornados são congelados (`Object.freeze`, profundo onde aplicável).

## Critérios de aceite

- [ ] `play` não altera o `Game` recebido (comparação profunda antes/depois) e retorna objeto congelado.
- [ ] Mate do pastor: `getStatus` → `checkmate`, vencedor brancas; `play` seguinte lança erro.
- [ ] Tripla repetição (`Nf3 Nf6 Ng1 Ng8` × 2) → `draw`/`threefold`.
- [ ] FEN com contador 99 + lance que dá mate → `checkmate`, não `fifty-move`.
- [ ] `undo` após 3 lances equivale a `createGame` + 2 lances (mesma FEN e histórico).
- [ ] `getLegalMovesFrom("e7")` com peão prestes a promover retorna os lances com `promotion` preenchido.
- [ ] `src/engine/index.ts` não exporta nada de `core` (teste que inspeciona as exportações).

## Para o verificador

Lance ilegal (inclusive promoção sem peça escolhida), `createGame` com FEN inválida, `undo` em partida vazia, imutabilidade de arrays retornados (`getHistory().push` deve falhar).
